# Exporters

Exporters collect metrics from the host machines. Prometheus exporters translate and expose system, database, and application metrics. Popular exporters collect specific categories of metrics:

##### System and Hardware Exporters
- Node Exporter: Collects Linux/Unix kernel hardware and OS statistics like CPU usage, memory utilization, disk I/O, and network traffic.
- Windows Exporter: Collects native Windows performance and system metrics like the Node Exporter
##### Database Exporters
- MySQL Exporter: Tracks query execution times, buffer pool status, and MariaDB / MySQL server performance.
- PostreSQL Exporter: Monitor connection counts, transaction rates, and database server health.
- Redis Exporter: Measures memory usage, keyspace activity, connected clients, and command statistics.
- MongoDB Exporter: Gathers collection stats, opcounters, and storage metrics.
##### Web Application Servers
- Nginx Exporter / Apache Exporter: Tracks active connections, request rates, and server status from web servers.
- PHP-FPM Exporter: Exposes worker process states and request pooling metrics.
##### Messaging and Streaming
- Kafka Exporter: Measures broker metrics, consumer group lag, and topic partitions.
- RabbitMQ Exporter: Tracks queue lengths, message rates, and node health.
##### Cloud and Infrastructure
- CloudWatch Exporter / Stackdriver Exporter / Azure Exporter: Pulls managed cloud provider from AWS, Google Cloud, and Azure into Prometheus formats.
- Blackbox Exporter: Performs active probing (HTTP,HTTPS, DNS TCP, ICMP) to test endpoint reachability and latency.
- kube-state-metrics: Listens to Kubernetes API Server to expose cluster objects (pods, deployments, nodes) as metrics.

##### Common Terms used across Metrics Monitoring
1. **Metric:** Numeric Value measured over time that tracks the health, performance, or behavior of the system.
2. **Scrape/Pull:** Action where a monitoring system like Prometheus actively fetches data from an exporter's HTTP endpoint.
3. **Push:** An alternative architecture where an application actively sends its metrics to a central collector.
4. **Endpoint:** The specific URL path (commonly `/metrics`) where exporters hosts its raw, plaintext monitoring data.
5. **Labels / Tags:** Key-value pairs attached to a metric to add context and allow filtering.
6. **Time Series:** Stream of timestamped values belonging to the same unique metric name and set of labels.
7. **Cardinality:** The total number of unique time series generated by combining a metric name with all possible label values. High cardinality overload monitoring systems.
8. **Target:** The specific service instance, server, or container that a monitoring system is configured to scrape.
9. **Alert Rule:** A condition written in a query language that triggers a notification if metrics cross a certain threshold.
